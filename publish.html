先上线，再买域名

推广开发者工具不一定先注册域名。更有效的顺序是：先把可读教程、可复制命令、可跑 demo 和 GitHub 链接上线，再根据反馈决定域名和长期文档框架。

需要域名吗 GitHub Pages 绑定自定义域名 内容结构 推广路径 下一步

需要注册域名吗

不需要一开始就买。对开源工具来说，第一阶段可以直接用 GitHub Pages 的免费地址：

https://<account>.github.io/<repo>/

这个地址足够放在 README、PyPI project URLs、GitHub About、issue 模板和社交媒体里。等站点内容稳定、项目名确定、搜索结果开始积累后，再买一个简短域名更划算。

如果目标是长期对外推广，域名有价值，但不是首要 blocker。首要问题是让第一次访问的人能在 3 分钟内安装、运行、理解 klink 解决什么问题。

用 GitHub Pages 上线

这个站点是纯静态文件，可以直接部署。推荐两种方式：

方式 A：独立网站仓库

git init
git add .
git commit -m "Add klink website"
git remote add origin https://github.com/<account>/klink-website.git
git push -u origin main

然后在 GitHub 仓库 Settings -> Pages，选择 `main` 分支和 `/root`。

方式 B：放进主仓库 `docs/`

如果希望网站跟代码仓同仓管理，可以把这些文件放到主仓库的 `docs/` 或 `website/`，再配置 Pages 来源。主仓已有 `docs/public/` 时要避免命名混乱，建议用独立 `website/` 或单独仓库。

绑定自定义域名

买域名之后，通常需要做三件事：

  1. 在 GitHub Pages 设置里填写 custom domain。
  2. 在仓库根目录添加 `CNAME` 文件，内容是一行域名，例如 `klink.dev` 或 `docs.klink.dev`。
  3. 在域名 DNS 面板添加记录。子域名常用 CNAME 指向 GitHub Pages 地址；根域名通常使用 GitHub Pages 文档指定的 A/AAAA 记录。

域名是否可注册会变化，注册前需要在域名服务商处实时查询。不要在文档里承诺某个域名可用。

推广路径

对 klink 这种工具，推广时不要先追求大而泛的 “AI EDA platform”。更实用的传播路径是：

  1. 首页主张：把 KLayout 中的自定义版图工作变成可验证、可复用的设计意图。
  2. 一条最短 demo：`klink init` -> 运行 starter -> 看到结构化结果。
  3. 一条 live demo：打开 KLayout -> plugin 监听 -> agent 读写几何并验证。
  4. 一条垂直 demo：硅光、纳米器件或 custom-device P&R 中选一个最强的做成 GIF/短视频。
  5. README 顶部增加“Start here”链接，指向快速上手页。
  6. GitHub release / PyPI project description / About URL 都指向同一个站点。

下一步建议

先部署 GitHub Pages

不用等域名。先让 README 和 GitHub About 链到一个比 README 更友好的入口。

补真实截图或短视频

当前站点已有生成主视觉。后续最好加入 KLayout live demo 的真实截图、录屏或 GIF。

把公开 docs 同步成站点内容

以后 release docs 更新时，同步检查网站页面，尤其是安装命令、demo 命令和依赖边界。

域名稳定后再绑定

项目名、包名和站点结构稳定后，再选择短域名并配置 CNAME。

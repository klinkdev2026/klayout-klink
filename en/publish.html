Launch first, buy a domain later

You do not need a domain on day one. For an open-source developer tool, a clear GitHub Pages site with runnable commands is more important than branding polish.

Need a domain? GitHub Pages Custom domain Content structure Promotion Next steps

Do you need a domain?

Not immediately. A free GitHub Pages URL is enough for the first release:

https://<account>.github.io/<repo>/

Use that URL in the README, PyPI project links, GitHub About, issue templates, and posts. Buy a short domain after the project name, package name, and site structure are stable.

The first goal is not brand polish. The first goal is that a new visitor can install, run, and understand klink in three minutes.

Deploy with GitHub Pages

Option A: separate website repository

git init
git add .
git commit -m "Add klink website"
git remote add origin https://github.com/<account>/klink-website.git
git push -u origin main

Then enable Pages in repository Settings and publish from the `main` branch root.

Option B: inside the main repository

You can place this site under `website/` or `docs/` in the main repository. Because the project already has `docs/public/`, a separate `website/` folder or separate repository is clearer.

Bind a custom domain

  1. Enter the custom domain in GitHub Pages settings.
  2. Add a root `CNAME` file containing one domain, such as `docs.example.dev`.
  3. Add DNS records at the registrar. Subdomains usually use CNAME; apex domains use the A/AAAA records specified by GitHub Pages documentation.

Domain availability changes constantly. Check availability at the registrar before committing to a name.

Promotion path

  1. Use the headline: turn custom KLayout work into verifiable, reusable design intent.
  2. Keep one shortest demo: `klink init` -> run starter -> see structured output.
  3. Show one live demo: KLayout plugin -> agent reads/writes geometry -> structured verification.
  4. Pick one vertical showcase: photonics, nanodevice, or custom-device P&R.
  5. Add a “Start here” link near the top of the GitHub README.
  6. Point GitHub release notes, PyPI project URLs, and the repository About URL to the same site.

Recommended next steps

Deploy GitHub Pages first

Do not wait for a domain. Give users a better entry point than a long README.

Add real screenshots or short clips

The site has a generated hero image. Later, add actual KLayout live-demo screenshots or GIFs.

Keep release docs and site in sync

When public docs change, re-check install commands, demo commands, and dependency boundaries here.

Bind a domain after the project stabilizes

Choose a short domain once the package name and positioning are settled.

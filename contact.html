联系 klink

klink 是一个早期试验阶段的开源项目，没有客服团队，也没有工单系统——所有沟通都走公开渠道。这一页说清楚三件事该往哪儿发：bug 和需求、提问和用法展示、代码贡献。

报 bug / 提需求 讨论与用法展示 贡献

报 bug / 提需求

报 bug 和提功能需求都走 GitHub Issues。klink 的发布节奏由真实用户反馈驱动——已经上线的好几个修复（工具可发现性、错误文案、starter 缺口）最初都是从一条用户 issue 开始的，不是自己闭门想出来的。

  • 中文、英文都欢迎，怎么顺手怎么写。
  • 描述越具体（版图规模、调用的 RPC/MCP 工具名、期望结果 vs 实际结果、能复现的最短步骤）修复越快；一句“不好用”很难定位。
  • 如果方便，贴上 klink.status 或相关工具的报错原文——错误文案本身通常已经指向下一步该做什么。

讨论与用法展示

提问同样欢迎发到 GitHub Issues——一个问题本身就是一条合格的 issue，不需要先确认是不是"真的算 bug"再发。

  • 想看项目全貌、README、发布历史，去 仓库主页。
  • 自助排查优先看 教程总览——大多数"怎么用 XX 工具"的问题已经有图文教程或对话案例覆盖。
  • 想晒一晒自己用 klink 画出来的版图或跑通的流程，同样开一个 issue，欢迎贴图贴脚本。

贡献

想提交代码或文档改动，先读仓库里的 CONTRIBUTING.md——里面是最新的分支、测试和提交约定。
